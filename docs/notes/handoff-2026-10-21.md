## 1. One command owns the probe checks

Before: the design phase's P0-5 probe's six steps (fmt, `rustfmt` on the helper, clippy, the 23
tests, the helper's 4 tests, the protocol checker) were written out three times —
in `ci.yml`, in `check.ps1`, and in xtask. Three copies drift.

- `xtask/src/main.rs` — new `Task::Probe` subcommand running exactly those six
  steps; `cargo xtask check` still includes them. Direct `Command` spawns of
  `cargo`, `rustfmt`, `rustc`, `python` only, no shell anywhere, so it runs
  wherever those binaries exist. `python3` is tried before `python`; if neither
  responds to `--version`, the protocol check prints "skipped" instead of
  failing (CI still enforces it). For a checkout reached over
  `\\wsl.localhost`, the helper's build is pointed at a Windows-local
  `CARGO_TARGET_DIR`, as `check.ps1` already did; an explicit env var wins.
- `.github/workflows/ci.yml` — the `probes` job is now checkout, toolchain,
  cache, `cargo xtask probe`, then the platform guard. The job-wide
  `defaults: run: shell: bash` is gone, so the Windows half touches no bash at
  all. The guard stays a workflow step on purpose: it asserts the binary's own
  exit codes (1 and 2), which is a property of the program, not of a command
  line. The rust-cache `workspaces:` list gained the workspace root because the
  job now builds `xtask`, which pulls in `acpilot-extensions` — the probe job is
  no longer independent of the workspace compiling.
- `probes/wsl-helper/check.ps1` — ~100 lines shorter; it now resolves the repo
  root and runs `cargo xtask probe`, and `-Wsl` does the same inside the distro
  via `wslpath` and the distro's own bash. `check.cmd` is unchanged (it only
  wrapped `check.ps1`).
- `docs/notes/wsl-helper.md`, `CONTRIBUTING.md` — describe `cargo xtask check` /
  `cargo xtask probe` as the command, with the scripts as thin wrappers.

## 2. The design phase's task P0-6 — the v1 API is frozen

- `docs/api.md` (new, 268 lines) — the frozen route list, the `X-Acpilot-Profile`
  convention, prompts as `202` + `turn_id` with a retry-safe `idempotency_key`,
  `409` for a second prompt while a turn is in flight, idempotent permission
  resolution, and the error envelope with its code → HTTP table. `Last-Event-ID`
  replay from the transcript, a 15 s heartbeat, `resync` instead of silence when
  an id cannot be replayed; pending permissions are state fetched on connect,
  not replayed history.
- `README.md` — the route list and the error envelope now match the frozen
  contract.
- `site/src/content/docs/flight-deck/api.md` — the short version, with the
  "Planned" table aligned to the frozen names.
- `TODO.md` — the design phase's task P0-6 checked off (line ~123) with a `Result:` paragraph recording
  what the review found.

The review's actual findings, all fixed in the document rather than noted:

| Gap | Fix |
| --- | --- |
| `AgentStatus::untrusted` had no way out | `POST /v1/agents/{id}/trust` |
| no host connection test | `POST /v1/hosts/{id}/test` |
| no profile activate / export | `POST /v1/profiles/{id}/activate`, `/export` |
| no directory listing | `GET /v1/files/list` |
| no profile-wide stream | `GET /v1/events` (`profile.*`, `daemon.*` only) |
| no error envelope in the README at all | the `{code, message, details}` table |

Three names had two spellings across documents; the frozen choice is
`permissions/{id}/resolve` (not `decide`), `/v1/lsp/servers` (not `/v1/lsp`), and
the flat `/v1/terminals?session=` (not nested). Providers, models, recipes and
the ACP bridge are deliberately post-v1.
