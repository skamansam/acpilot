**The autopilot is very good. That is exactly the problem.** Acpilot is a code

that opinion practical.

## What this is

Acpilot is a code editor and an agent cockpit in one program. It speaks the
**Agent Client Protocol** to agents that support it, and it can also fly
programs that have never heard of ACP — a terminal agent, a CLI, anything that
prints a transcript.

One daemon owns the sessions, the agents, the permissions, and the terminals.
The CLI, the terminal UI, the desktop app, and the browser are all clients of
that daemon, which is why they never disagree about what happened.

## The shape of a flight

```bash
acpilot tui                      # open the cockpit on this machine
acpilot watch build             # follow a session from another terminal
acpilot --profile work agents ls  # who is available under work credentials?
```

Those three lines are the destination, not the current position. The
[flight status](status/) page says exactly how much of this exists today,
because a manual that lies about the aircraft is worse than no manual.

## What it is not

- **Not a chat window with a file tree.** The editor is the product; the agent is
  a crew member, not the pilot.
- **Not a cloud service.** Your machine, your daemon, your keys.
- **Not a promise that the agent is right.** It is a promise that you will see
  what it did before it counts.
