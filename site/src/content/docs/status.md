The footer's stats bar draws a context and a credit track per integration, and `F4` names where each figure came from. The 200×60 drawing is held to a 16.7 ms frame budget by a CI job |
| Text model | <span class="pill pill--boarding">boarding</span> | `acpilot-text`, the crate every editor pane will edit through: a character-indexed rope that keeps a file's line endings and byte-order mark, selection sets with motions, edits as replacements, and an undo history that groups a typed run. `pane` adds the viewport arithmetic a renderer needs: which rows are on screen, what survives the horizontal scroll (tabs and double-width characters measured in cells), where the caret lands, and what `/` found. Tested with property tests (undo-then-redo is the identity, no caret leaves the text, no offset panics, no row wider than its viewport). The TUI's editor pane draws it |

| Integration stats | <span class="pill pill--boarding">boarding</span> | `GET /v1/stats` lists one row per configured agent, and `acpilot-stats` turns a row into a track and a sentence for every surface: the TUI draws it in the footer (`F4` names each figure's source), the desktop app in its own, and the daemon serves the measured rows to the page at `/app/stats`. The context figure is counted by the sessions engine from the events a conversation carries (the agent's own usage update wins when it sends one), so an agent with a session shows an estimated `18.4k / ?` and one without shows nothing at all. An unknown denominator is drawn as an indeterminate track, never full or empty. No provider rows or balances yet — that is P4.5-12 |
| Panels | <span class="pill pill--boarding">boarding</span> | The TUI's window is an editor with a column either side, and the Panels menu (`Alt-P`) puts the **file manager**, the **outline**, the **references** list and the **assistant** on the side a person wants. The outline lists the open buffer's definitions from the grammar it is highlighted with and re-reads them as the buffer is edited; **references** (`Shift-F12`) lists the code uses of the identifier under the caret, from `GET /v1/files/references`, with the parse tree keeping comments and strings out of the list and `Enter` opening the file at the use. Two more panels are designed and not built — a **project map** the agent writes under `.acpilot/` and a **wiki** of linked pages per subsystem — with their shape written down in [the TUI page](/acpilot/flight-deck/tui/#panels) and `TODO.md` |
| Git diff and tree | <span class="pill pill--flying">flying</span> | `acpilot-git` reads status, diffs, tree and log from the system `git`; the tree's letters and the editor's gutter are served by `GET /v1/files` and `/v1/files/list`, and `GET /v1/git/status`, `/diff`, `/tree` and `/log` serve the repository itself. All three surfaces read the same routes and draw separate unstaged and staged halves of the daemon's patch: the TUI's `F6` pane and the desktop app's `F6` overlay cut it with the same `acpilot-git` helper, and the browser's **Source control** panel reads only when opened. Each surface can stage one unstaged hunk through `POST /v1/git/stage-hunk` — `h`/`l` then `Shift-S` in the TUI and desktop app, **Stage hunk N of M** in the browser — and stages the selected path through `POST /v1/git/stage` and `/unstage` — `s`/`u` in the TUI and desktop app, **Stage path**/**Unstage** in the browser. `d`/`x` (TUI and desktop) or **Discard**/**Checkout** (browser) restore the path through `/v1/git/discard` or `/v1/git/checkout`; each arms behind a confirmation. Discard keeps staged changes, checkout resets both halves to `HEAD`, and checkout is unavailable before the first commit |
| Commit messages | <span class="pill pill--flying">flying</span> | The TUI composer opens with `c`, drafts from the open session with `Ctrl-G` through `POST /v1/git/commit-message`, and commits the staged index with `Ctrl-S` then `y` through `POST /v1/git/commit`. The message is editable before the confirmation, and the commit route never stages: the pane's `s`/`u` prepare the index first. The desktop overlay uses the same `F6`, `s`/`u` and `c`/`Ctrl-G`/`Ctrl-S`/`y` path, and `Tab`/`Shift-Tab` in its composer chooses which listed session drafts the message. The browser's panel generates a draft into an editable composer whose `Review commit` is the step before `Commit staged index`. Discard and checkout are separate confirmed actions, so a commit never silently reverts a path |

## How this page stays honest

The phases come from `TODO.md` in the repository, which is the source of truth.
When a phase lands, its row here changes in the same pull request — a status page
that drifts is just a rumour with better typography.

<Aside type="tip" title="Why publish this at all">
Because "coming soon" is what people write when they mean "not started". A
numbered phase with a visible state is the same information without the
marketing.
</Aside>
